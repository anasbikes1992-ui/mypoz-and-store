## Runbook (who / how)

### A. Daily / weekly logical export (operator)

1. Ensure `SUPABASE_DB_PASSWORD` in local env (never commit).  
2. `node --env-file=.env.local scripts/gate5-logical-export.mjs`  
3. Copy `data/backups/gate5-logical-*.json` + `.meta.json` to off-site storage (immutable preferred).  
4. Remember: **DB backup ≠ Storage objects** — media must be backed up separately if used.

### B. Cert script (CI / laptop)

```bash
node --env-file=.env.local scripts/gate5-dr-cert.mjs
```

### C. Restore drill (disposable — do not run against prod casually)

1. Supabase Dashboard: create **branch** or new project from backup / PITR.  
2. Or: empty project → apply repo migrations `0001`–`0030` → import logical JSON with a controlled loader (map FKs if IDs collide).  
3. Run `data/backups/gate5-restore-verify.sql`.  
4. Expect: `tables_without_rls = 0`, critical RPCs true, migration_rows ≥ 31.  
5. Point a Preview Vercel env at the restored project; smoke `/api/health` (or equivalent) + one authenticated cash sale.  
6. Rotate any secrets copied into the drill env.  
7. Delete the disposable branch/project when done.

### D. Secrets rotation after real incident restore

Rotate: Supabase anon/service keys, WebXPay keys if exposed, WhatsApp tokens, Gate 3 test passwords, Vercel env.
